2~3명이 한 팀이 되어 5일 동안 하나의 비전 프로그램을 완성합니다. 난이도 4단계 중 우리 팀에 맞는 주제를 고르세요.

프로젝트 안내

이 프로젝트는 교과 3에서 배운 OpenCV 기술을 실제로 쓸 수 있는 도구 하나로 묶어 보는 시간입니다. 12개 주제는 모두 앞으로 이어질 교과 7(라벨링), 교과 9(머신비전), 교과 14·15(최종 프로젝트)와 연결되어 있어서, 여기서 만든 코드를 뒤에서 다시 쓰게 됩니다.

기간5일
개발 환경Windows 11 + Anaconda 가상환경, Python 3.9 또는 3.10
사용 라이브러리OpenCV(contrib 포함), NumPy, pandas, matplotlib

이번 프로젝트에서는 딥러닝을 쓰지 않습니다

YOLO나 CNN 같은 딥러닝 모델은 교과 5와 교과 8에서 배웁니다. 이번에는 규칙(임계값, 색 범위, 모양 조건)만으로 어디까지 풀 수 있는지 직접 확인하는 것이 목적입니다. 규칙으로 풀리지 않는 지점을 정확히 찾아내면, 나중에 딥러닝이 왜 필요한지 훨씬 빨리 이해하게 됩니다.

# utils.py — 모든 팀이 공통으로 쓰는 도우미 함수
import json
import os
import time
from collections import deque

import cv2
import numpy as np


def imread_unicode(path, flags=cv2.IMREAD_COLOR):
    """한글이 들어간 경로도 읽을 수 있는 imread. 실패하면 None."""
    if not os.path.exists(path):
        return None
    data = np.fromfile(path, dtype=np.uint8)
    return cv2.imdecode(data, flags)


def imwrite_unicode(path, img, params=None):
    """한글이 들어간 경로에도 저장할 수 있는 imwrite. 성공하면 True."""
    ext = os.path.splitext(path)[1]
    ok, buf = cv2.imencode(ext, img, params or [])
    if ok:
        buf.tofile(path)
    return ok


def open_source(source):
    """'0','1' 같은 숫자면 웹캠, 그 외에는 동영상 파일로 연다."""
    if str(source).isdigit():
        # Windows에서는 DirectShow(CAP_DSHOW)로 열면 카메라가 빨리 켜집니다.
        cap = cv2.VideoCapture(int(source), cv2.CAP_DSHOW)
    else:
        cap = cv2.VideoCapture(source)
    if not cap.isOpened():
        raise SystemExit(f"[ERROR] 입력을 열 수 없습니다: {source}")
    return cap


class FPSMeter:
    """최근 N프레임 이동평균으로 FPS를 계산한다."""

    def __init__(self, window=30):
        self.intervals = deque(maxlen=window)
        self.last = time.perf_counter()

    def tick(self):
        now = time.perf_counter()
        self.intervals.append(now - self.last)
        self.last = now
        total = sum(self.intervals)
        return len(self.intervals) / total if total > 0 else 0.0


def load_config(path=None):
    """조정할 값들을 config.json에서 읽어 딕셔너리로 돌려준다.
    path를 주지 않으면 프로젝트 폴더(src의 상위)의 config.json을 읽는다."""
    if path is None:
        path = os.path.join(os.path.dirname(os.path.abspath(__file__)), "..", "config.json")
    with open(path, encoding="utf-8") as f:
        return json.load(f)

imread_unicode가 왜 필요한가요?

Windows에서 cv2.imread는 경로에 한글이 들어 있으면 오류 없이 None을 돌려줍니다. 그다음 줄에서 img.shape를 부르면 'NoneType' object has no attribute 'shape' 오류가 납니다. imread_unicode는 파일을 바이트로 먼저 읽고 cv2.imdecode로 해석해서 이 문제를 피합니다.

영상 주제의 시작 뼈대

웹캠과 동영상 파일을 --source 인자 하나로 바꿀 수 있게 만든 기본 구조입니다. process() 함수 안만 채우면 됩니다. 녹화해 둔 영상 파일로 시험하면 같은 조건에서 몇 번이고 다시 잴 수 있어서 기준값을 조정할 때 훨씬 편합니다.

Python 파일src/main.py
# main.py — 영상 입력 주제 공통 뼈대
import argparse

import cv2

from utils import FPSMeter, open_source


def process(frame):
    """팀이 구현할 처리 함수. 지금은 그레이스케일 변환만 한다."""
    gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)
    return cv2.cvtColor(gray, cv2.COLOR_GRAY2BGR)


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--source", default="0", help="0=웹캠, 또는 동영상 파일 경로")
    args = ap.parse_args()

    cap = open_source(args.source)
    fps = FPSMeter()

    while True:
        ok, frame = cap.read()
        if not ok:
            print("[INFO] 영상이 끝났거나 프레임을 읽지 못했습니다.")
            break

        out = process(frame)
        cv2.putText(out, f"FPS {fps.tick():.1f}", (10, 30),
                    cv2.FONT_HERSHEY_SIMPLEX, 0.8, (0, 255, 0), 2)
        cv2.imshow("result", out)

        if cv2.waitKey(1) & 0xFF == ord("q"):
            break

    cap.release()
    cv2.destroyAllWindows()


if __name__ == "__main__":
    main()

비스듬히 찍힌 문서나 제품 라벨을 자동으로 찾아 정면에서 찍은 것처럼 펴 주는 스캐너입니다.

왜 이 프로젝트인가요?

제품 라벨, 바코드, 계기판 화면은 정면에서 찍히지 않는 경우가 대부분입니다. 검사나 판독 전에 이미지를 정면으로 펴는 작업은 머신비전의 기본 전처리이고, 카메라 좌표 변환을 이해하는 첫걸음입니다.

필수 기능

  1. 입력 이미지에서 가장 큰 사각형 영역을 자동으로 찾습니다(에지 → 외곽선 → 사각형 근사).
  2. 꼭짓점 4개를 왼쪽 위 → 오른쪽 위 → 오른쪽 아래 → 왼쪽 아래 순서로 정렬합니다.
  3. 투영 변환으로 정면 이미지를 만들고, 출력 크기는 원래 변 길이로 계산합니다.
  4. 결과를 컬러 / 흑백(적응형 이진화) / 선명하게(샤프닝) 세 가지 모드로 바꿔 보고 저장합니다.

도전 기능 (창의성 가산점)

  • 자동 검출에 실패하면 마우스로 네 점을 직접 찍는 수동 모드
  • 웹캠 실시간 스캔 — 사각형이 몇 프레임 연속 안정적으로 잡히면 자동 촬영
  • 여러 장 스캔 결과를 한 파일로 묶어 저장
  • CLAHE로 밝기를 고르게 한 뒤 글씨 가독성 비교

사용할 기술

지정한 위험 구역에 사람이나 물체가 들어오면 경고를 띄우고, 사건이 일어나기 전후 구간을 잘라 영상으로 자동 저장하는 감시 시스템입니다.

왜 이 프로젝트인가요?

산업안전 CCTV 분석의 기본 기능입니다. 교과 15 「산업현장 수신호 자세체험 솔루션」의 실시간 알림 부분을 자세 추정 없이 움직임만으로 먼저 구현해 봅니다.

필수 기능

  1. 마우스로 위험 구역을 다각형으로 지정하고 JSON으로 저장·불러오기
  2. 움직임을 검출하고 구역 안인지 판정하되, N프레임 이상 계속될 때만 침입으로 확정해 오경보를 줄입니다.
  3. 상태 전환을 명확히 관리합니다 — 대기 → 감지 중 → 경보 → 해제. 화면에 현재 상태를 표시하고, 경보 때는 화면 테두리를 빨갛게 하고 경고 문구를 띄웁니다.
  4. 사건 영상 자동 저장 — 발생 시점 기준 이전 3초 + 이후 5초를 저장하고, 사건 기록(시각·지속 시간·구역 이름)을 CSV로 남깁니다.

도전 기능 (창의성 가산점)

  • 광학 흐름으로 이동 방향·속도를 구해 "빠르게 접근 중" 단계 경고
  • 주의 구역 / 금지 구역을 여러 개 두고 단계별로 다르게 경고
  • 하루 동안 어디에서 침입이 잦았는지 보여 주는 히트맵 이미지
  • 어두운 환경 대응(CLAHE, 감마 보정)과 야간 모드

P12

실시간 처리 속도 최적화 — 멀티스레드와 성능 측정

Level 4 ★★★★권장 인원 2~3명기간 5일

같은 영상 처리 흐름을 단순 반복 → 멀티스레드 → 최적화 버전으로 단계별로 개선하면서, FPS가 얼마나 달라지는지 숫자로 증명하는 엔지니어링 프로젝트입니다.

왜 이 프로젝트인가요?

교과 14는 Jetson Orin Nano Super에서 20 FPS 이상, 교과 15는 PC에서 30 FPS 이상이 목표입니다. 모델을 바꾸지 않아도 처리 구조만 바꿔서 속도가 2~3배 달라질 수 있다는 것을 직접 재서 확인합니다. 최종 프로젝트에서 속도가 부족할 때 가장 먼저 손대야 할 곳입니다.

필수 기능

  1. 공통 처리 흐름 정의 — 전처리(크기 줄이기·블러) → 검출(에지 또는 색 분리) → 후처리(모폴로지·외곽선) → 결과 그리기
  2. 세 가지 버전 구현 — ① 단순 반복 ② 읽기·처리 스레드 분리(큐 사용) ③ 최적화 적용
  3. 단계별 시간 측정 — 단계마다 걸린 시간(ms)을 따로 재고, 가장 느린 단계를 화면에 표시
  4. 해상도 3종 × 버전 3종 FPS 비교표와 그래프(matplotlib)를 자동으로 만들어 저장

도전 기능 (최적화 기법 — 최소 4가지 이상 실험)

  • 처리는 작은 해상도로 하고 결과 좌표만 원래 크기로 되돌리기
  • 관심 영역(ROI)만 처리하기
  • NumPy 반복문을 벡터 연산으로 바꾸기
  • 무거운 연산은 N프레임마다 한 번만 하고 나머지는 결과 재사용
  • cv2.UMat(OpenCL 가속) 적용 전후 비교
  • cv2.setNumThreads 값에 따른 변화 측정
  • 큐 크기를 제한하고 오래된 프레임은 버려서 지연이 쌓이지 않게 하기

사용할 기술

동시 처리threading.Thread, queue.Queue(maxsize=N), threading.Event(안전한 종료)
측정time.perf_counter, cv2.getTickCount, 단계별 누적 통계, 이동평균 FPS
가속cv2.UMat, cv2.ocl.setUseOpenCL, cv2.setNumThreads, cv2.resize 보간법(INTER_NEAREST / INTER_AREA) 비교
보고서pandas 집계 + matplotlib 그래프 저장

막히기 쉬운 지점과 힌트
  • cv2.imshow와 cv2.waitKey는 반드시 메인 스레드에서 불러야 합니다. 화면 표시만 따로 스레드로 빼면 프로그램이 멈추거나 창이 뜨지 않습니다.
  • 큐 크기를 제한하지 않으면 처리가 밀릴 때 지연이 끝없이 쌓입니다. maxsize를 두고, 가득 차면 오래된 프레임을 버리는 것이 실시간 시스템의 정석입니다.
  • 종료할 때 스레드가 남아 프로그램이 안 꺼지는 문제가 흔합니다. Event 플래그로 멈추라고 알리고 join()으로 기다리세요.
  • 파이썬의 GIL 때문에 순수 파이썬 계산은 스레드를 나눠도 빨라지지 않습니다. 그런데 OpenCV 내부 연산과 카메라 읽기 대기 시간에는 GIL이 풀려서 효과가 납니다. 이 이유를 발표에서 설명할 수 있으면 만점입니다.
  • 측정값은 매번 조금씩 다릅니다. 3회 평균과 함께 표준편차도 제시하세요.
